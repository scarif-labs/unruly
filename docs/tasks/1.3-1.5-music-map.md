## A. Library exposure

- `org.oxycblt.musikr.Library` is the immutable library contract. It exposes `songs`, `albums`, `artists`, `genres`, and `playlists` as `Collection` properties (`musikr/src/main/java/org/oxycblt/musikr/Library.kt:28`).
- `org.oxycblt.musikr.LibraryResult.library` returns the indexed `MutableLibrary` from `Musikr.run` (`musikr/src/main/java/org/oxycblt/musikr/Musikr.kt:55`, `musikr/src/main/java/org/oxycblt/musikr/Musikr.kt:79`).
- The concrete graph-backed holder is `org.oxycblt.musikr.model.LibraryImpl`, an internal data class storing `Set<SongImpl>`, `Set<AlbumImpl>`, `Set<ArtistImpl>`, `Set<GenreImpl>`, and `Set<PlaylistImpl>` (`musikr/src/main/java/org/oxycblt/musikr/model/LibraryImpl.kt:30`).
- The app-level holder is `org.oxycblt.auxio.music.MusicRepository`. Its public property is `library: Library?` (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:63`, `app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:65`). Its implementation stores `MutableLibrary?` (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:240`, `app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:253`).
- `MusicRepository` is not a `StateFlow` or `LiveData`; consumers receive changes through `UpdateListener.onMusicChanges(Changes)` (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:182`, `app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:189`).

Materialised song lists:

- Raw accessor: `Library.songs: Collection<Song>` (`musikr/src/main/java/org/oxycblt/musikr/Library.kt:29`).
- Concrete accessor: `LibraryImpl.songs: Set<SongImpl>` (`musikr/src/main/java/org/oxycblt/musikr/model/LibraryImpl.kt:31`).
- UI wrapper: `HomeGenerator.songs(): List<Song>` (`app/src/main/java/org/oxycblt/auxio/home/HomeGenerator.kt:41`), implemented by sorting `musicRepository.library.songs` (`app/src/main/java/org/oxycblt/auxio/home/HomeGenerator.kt:153`).
- ViewModel wrapper: `HomeViewModel.songList: StateFlow<List<Song>>` (`app/src/main/java/org/oxycblt/auxio/home/HomeViewModel.kt:55`, `app/src/main/java/org/oxycblt/auxio/home/HomeViewModel.kt:57`).

Thus, the Musikr library has no `List<Song>` accessor, but the app UI does expose a materialised list through `HomeViewModel.songList`.

## C. Load state

The app state is `org.oxycblt.auxio.music.IndexingState`, a sealed interface (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:223`):

- `IndexingState.Indexing(progress: IndexingProgress)` means scanning/indexing (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:229`).
- `IndexingProgress.Songs(loaded: Int, explored: Int)` reports extracted and discovered song counts (`musikr/src/main/java/org/oxycblt/musikr/Musikr.kt:93`, `musikr/src/main/java/org/oxycblt/musikr/Musikr.kt:100`).
- `IndexingProgress.Indeterminate` represents graph construction/finalization without measurable progress (`musikr/src/main/java/org/oxycblt/musikr/Musikr.kt:107`).
- `IndexingState.Completed(error: Exception?)` represents completion (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:237`). `error == null` is ready/success; non-null is an error state.
- `indexingState` is nullable before the first load (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:67`, `app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:68`).

Observation:

- Repository consumers register `MusicRepository.IndexingListener`; changes arrive through `onIndexingStateChanged()` (`app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:200`, `app/src/main/java/org/oxycblt/auxio/music/MusicRepository.kt:203`).
- `MusicViewModel.indexingState` exposes `StateFlow<IndexingState?>` (`app/src/main/java/org/oxycblt/auxio/music/MusicViewModel.kt:60`, `app/src/main/java/org/oxycblt/auxio/music/MusicViewModel.kt:63`).

- `Song.cover: Cover?` is passed to `CoverView` (`musikr/src/main/java/org/oxycblt/musikr/Music.kt:307`, `app/src/main/java/org/oxycblt/auxio/image/CoverView.kt:348`, `app/src/main/java/org/oxycblt/auxio/image/CoverView.kt:350`).
- `ImageRequest.Builder.data(...)` receives that model (`app/src/main/java/org/oxycblt/auxio/image/CoverView.kt:511`, `app/src/main/java/org/oxycblt/auxio/image/CoverView.kt:513`).
- `CoverFetcher` opens the cover stream through `Cover.open()` (`app/src/main/java/org/oxycblt/auxio/image/coil/CoverFetcher.kt:35`, `app/src/main/java/org/oxycblt/auxio/image/coil/CoverFetcher.kt:37`).
- Cache key: `"${data.id}&${options.size}"`; `Cover.id` is a `String` (`app/src/main/java/org/oxycblt/auxio/image/coil/CoverFetcher.kt:50`, `app/src/main/java/org/oxycblt/auxio/image/coil/CoverFetcher.kt:51`, `musikr/src/main/java/org/oxycblt/musikr/covers/Covers.kt:102`, `musikr/src/main/java/org/oxycblt/musikr/covers/Covers.kt:107`).

For albums:

- `Album.covers: CoverCollection` is grouped by cover ID.
- `CoverView.bind(album)` selects the most frequent `Cover` and passes that concrete `Cover` to Coil (`musikr/src/main/java/org/oxycblt/musikr/Music.kt:342`, `app/src/main/java/org/oxycblt/auxio/image/CoverView.kt:361`, `app/src/main/java/org/oxycblt/auxio/image/CoverView.kt:368`, `app/src/main/java/org/oxycblt/auxio/image/CoverView.kt:373`).

Artwork source:

- Embedded tags are handled by `EmbeddedCovers`; it reads `metadata.cover` and creates an `EmbeddedCover` (`musikr/src/main/java/org/oxycblt/musikr/covers/embedded/EmbeddedCovers.kt:44`, `musikr/src/main/java/org/oxycblt/musikr/covers/embedded/EmbeddedCovers.kt:47`, `musikr/src/main/java/org/oxycblt/musikr/covers/embedded/EmbeddedCovers.kt:50`).

- `SettingCoversImpl` chains stored embedded covers with filesystem covers (`musikr/src/main/java/org/oxycblt/auxio/image/covers/SettingCovers.kt:52`, `musikr/src/main/java/org/oxycblt/auxio/image/covers/SettingCovers.kt:65`, `musikr/src/main/java/org/oxycblt/auxio/image/covers/SettingCovers.kt:71`).
