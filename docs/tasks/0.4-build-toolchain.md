## 🔴 The buildspec's JDK version is wrong

**Buildspec 0.2 says "JDK 17". The project requires JDK 21.**

Evidence:
- `app/build.gradle:33-34` — `sourceCompatibility JavaVersion.VERSION_21`, `targetCompatibility JavaVersion.VERSION_21`
- `app/build.gradle:78` — `jvmTarget = JvmTarget.JVM_21`
- `musikr/build.gradle:44-45` — same
- Auxio `README.md:120` — "Install Java-21 with your system package manager"

The machine had JDK **17** and **26**, neither usable: 17 cannot compile source level 21,
and 26 is far ahead of AGP 9.2.1's supported range.

Following the buildspec literally here would have produced a build failure whose error
message points nowhere near the actual cause. This is exactly the class of problem the
spec warns about — and the spec itself was the source of it.

## Papercuts

**1. `brew install --cask temurin@21` fails in a non-interactive shell.**
The cask installs to `/Library/JavaVirtualMachines`, which needs root:

```
==> Running installer for temurin@21 with `sudo` (which may request your password)...
sudo: a terminal is required to read the password
Error: Failure while executing; `/usr/bin/sudo ... /usr/sbin/installer -pkg ...` exited with 1
```

**Resolution — install the JDK user-locally, no sudo:**

```bash
mkdir -p ~/.jdks && cd ~/.jdks
curl -sL -o t21.tar.gz \
  "https://api.adoptium.net/v3/binary/latest/21/ga/mac/aarch64/jdk/hotspot/normal/eclipse"
tar xzf t21.tar.gz
```

Then point Gradle at it explicitly rather than mutating the machine default — pinning the
toolchain per-project is the better outcome regardless of the sudo issue.

**2. `cmd 2>&1 | tail -N` masks the real exit code.**
The failed cask install was reported as **exit 0** because a pipeline returns the exit
status of its *last* command (`tail`), not the first. This turned a hard failure into a
silent success in the task notification. Use `set -o pipefail`, or check the log contents
rather than trusting the reported status, for any install or build run through a pipe.
**Applies directly to the Gradle build** — never judge `./gradlew … | tail` by its exit code.

**3. `/usr/libexec/java_home -v 21` silently returns the wrong JDK.**
With no JDK 21 present it returned the **26** home rather than failing. A script that trusts
it would run the build on an unsupported JDK and produce a baffling error. Verify with
`java -version` on the resolved path, not with `java_home`'s exit status.

**4. `cmake` is now `4.4.2` (Homebrew).**
The README requires `cmake` + `ninja` installed, and they now are (`ninja 1.13.2`).
⚠️ CMake **4.x removed compatibility with `cmake_minimum_required(VERSION <3.5)`**, which
older native projects (taglib, ffmpeg) can still declare. AGP normally prefers the
SDK-bundled CMake `3.22.1`, so this should not bite — but **if the native build fails with
a `cmake_minimum_required` / policy error, this is the cause**, and the fix is to force the
SDK CMake rather than downgrading Homebrew.
