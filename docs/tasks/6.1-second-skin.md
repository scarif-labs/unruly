## 1. Why this is the important phase

Every skin so far was written alongside the contract, by people who knew what the contract was
shaped for. This one had to be different in every axis that matters:

| | Touch Wheel | Zune |
|---|---|---|
| Input | Rotation + 5 zones | Touch |
| Navigation | Drill-down hierarchy | Horizontal pivot (`HorizontalPager`) |
| List model | Selection index the wheel drives | Direct tap |
| Visual language | White, bezelled, 4:3 face | Black, oversized lowercase type, one accent |
| Search | Wheel-driven character selection | Text field |

**The gates that matter both passed:**

```
grep -rc "org.oxycblt"            skin/.../zune/   -> 0
grep -rn "org.unruly.skin.wheel" skin/.../zune/   -> nothing
```

1,074 lines of complete music-player UI written against nothing but the contract and the
shared `support/` layer. No engine imports, and — just as importantly — **no reach into the
first skin**. That second gate is what distinguishes "the contract generalises" from "the
second skin quietly reused the first one's plumbing".

---

## 2. Contract feedback

The agent reported **no contract gap that blocked implementation**, which is a meaningfully
different result from 5e (where the first real skin found a genuine hole in `SkinCommands`).
The fixes made after 5e — the `playSongFrom*` family especially — held up under an
independent consumer.

Two pieces of friction it did raise:

1. **Plain-`List` flows expose no independent loading state.** `songsByAlbum` and
   `songsByPlaylist` return `Flow<List<SkinSong>>`, so a screen showing one has no way to
   distinguish "still loading" from "genuinely empty", and has to lean on the global
   `SkinLibraryGate`. In practice fine, but it is the second time the paged/plain asymmetry
   has cost a consumer something (see [5e](5e-menu-hierarchy.md) §5.3). **Two independent
   skins have now both paid for it — that is the threshold at which it should be revisited.**
2. **Non-composable back handling forces a field-held stack.** Same constraint the wheel skin
   hit. Both skins independently reached for `SkinBackStack`, which suggests the support-layer
   answer is the right one, but it is worth noting the contract *requires* a workaround rather
   than offering an idiom.

## 3. Defects found on device

All three were visual, and all three are the kind that compile and run perfectly.

**Headings wrapped instead of clipping.** `music` rendered as `mu / sic`; the pivot's
`playlists` as `playli / sts`. The prompt asked for oversized headings that *bleed past the
right edge* — that overflow is the signature of the visual language. Compose's default is to
wrap, which turns a deliberate design choice into what looks like a layout bug. Fixed with
`maxLines = 1`, `softWrap = false`, `overflow = TextOverflow.Clip`.

**The pivot row could not be scrolled.** Once headings clip rather than wrap, the trailing
ones become unreachable — a plain `Row` compresses its children to fit rather than letting
them run off. Added `horizontalScroll`, so "clipped at the edge" stays a visual effect instead
of becoming a dead control.

These two are a pair worth remembering: **making text overflow deliberately also requires
making the overflowed content reachable.** Fixing only the first produces a prettier screen
with a broken pivot.

**`1 songs`.** Trivial, but user-visible. Added a `plural` helper.

**Headings were truncated even after the clip fix** (`music` → `mus`, `now playing` cut
mid-glyph). The clip fix was necessary but not sufficient: the heading shared a `Row` with the
utility links and took `weight(1f)`, so the links claimed their width *first* and the heading
got the remainder. A four-letter word was losing a fight with a row of links.

The deliberate bleed is for genuinely long headings running off the screen edge — not for
short ones being squeezed by a sibling. Fixed by giving the heading a full-width line of its
own with the links beneath it.

Worth noting as a pattern: **the first fix addressed the symptom at the wrong layer.** Clipping
vs wrapping was a real bug, but the truncation the user saw was a layout-constraint problem,
and no text-overflow setting could have solved it.

**Now-playing was a centred thumbnail.** A 250dp square in an otherwise empty column — a
generic music app, not this one. On the hardware being matched, the artwork *is* the screen:
full bleed, with track details over its lower half. Rebuilt that way, with details and controls
hanging off the same left margin as every other screen instead of being centred.

The scrim needed two passes. The first ramp was too gentle and left the cover's own lettering
visible behind the progress bar — two sets of type fighting each other. It now reaches
near-solid well above the text block.

## 4. Papercut: anchor a code insert to the file that actually contains it

Inserting the `plural` helper anchored on `internal fun formatDuration(...)`, assuming it was
in `ZuneScreens.kt` because that is where the agent's report showed it. It was in
`ZuneTheme.kt`. The string replace silently matched nothing, so the *call sites* were rewritten
while the *definition* was never added — seven `Unresolved reference 'plural'` errors.

Harmless because the compiler caught it, but the general shape is worth noting: a
find-and-replace whose anchor does not match **fails silently and leaves the edit half
applied**. Verify the anchor exists before relying on it, or check the result rather than the
exit status — the same lesson as [PAPERCUTS §1](../PAPERCUTS.md).

## 6. What this establishes for the buildspec

Phase 6.1 asks for "a second skin that proves the contract is not shaped around the first".
That is met: two skins with no shared code beyond `support/`, no engine access, both driving
the same engine correctly, switchable at runtime.

The stronger evidence is the *absence* of contract changes. 5e needed a new command family
before the first real skin could work. 6.1 needed none.

## 7. Rebuilt from the hardware (2026-10-20, uncommitted)

A first pass from memory was rejected. The user supplied a Zune HD walkthrough video
(Jon Rettinger, "Zune HD Interface Walkthrough") and asked for an exact replica. The skin was
rebuilt from frames of it; the key frames and contact sheets are in
`~/Desktop/Unruly Zune Reference/`. Checked on device in portrait against those frames.

- **Type**: Selawik (Microsoft's OFL metric match for Segoe UI), five weights in
  `skin/src/main/res/font/`, licence in `skin/LICENSE-Selawik-OFL.txt`. This is the first
  resource the `:skin` module carries. Two voices: light/regular mixed or lower case for things
  you navigate by, bold capitals (`CapsBold`) for names; `CapsSmall` lavender capitals for
  metadata. Lavender (`ZuneLavender`) is the only secondary colour.
- **Home** (`SkinDestination.Home`, the root): lower-case menu items each with a tiny capitals
  sub-label; a play ring beside "music" opens now playing. Quickplay (Playing / History / New)
  sits shrunk in the left gutter; dragging right grows it while the menu shrinks into a small
  right-hand column. One `Animatable` 0..1 drives both layers. History is the skin's own
  (`ZuneHistory`, a private prefs file of recently played album ids), because the contract has
  none; one instance is shared through `ZuneSkin.rememberHistory()`.
- **Music hub**: giant "music" cropped by the top edge in a lavender-to-aqua gradient
  (`GiantHeading`), bold capitals pivots that loop in the hardware's order (artists, playlists,
  songs, genres, albums) with the active one first, via a 5,000-page pager started mid-way.
  Artist/genre/playlist rows: play ring, bold name, detail. Album rows: large cover with a play
  ring, title, artist, first six track names in tiny dim type.
- **Now playing**: back ring, artist in bold caps, album in light caps, cover at 64% width with a
  thin seek bar and times, title (tap for the queue), the next three songs, and shuffle / repeat
  / lyrics rings. Tap: transport overlay (EXIT, system media volume as a big number with + and
  -, large skip and play ring, artist and title in the corner), auto-hides after 4 s. Untouched
  for 20 s: ambient mode, details fade, the album title's words tumble across the cover. The
  backdrop is the cover blurred and greyscaled (`RenderEffect`, API 31+).
- **Queue**: playing title as the giant heading, "n OF m", rows with the playing song's length in
  the gutter.

Deviations from the video, all forced by what the app has: the third now-playing ring opens
lyrics instead of rating (no ratings); the backdrop uses the cover (no artist photos); the home
menu lists only music, queue, lyrics, search, settings; no Pins.

Testing note: the 20 s idle mode will swallow the next tap (it only wakes the screen), which
looked like a broken overlay while testing slowly. It is not a bug.

Not verified yet: search, artist/album/genre/playlist detail pages, the lyrics screen in the new
type, landscape, and History filling in after a second album plays.
