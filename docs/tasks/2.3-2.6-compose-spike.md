## Papercuts

### 1. 🔥 codex agents cannot run Gradle in this project

```
java.net.SocketException: Operation not permitted
```

`codex exec --sandbox workspace-write` blocks the **UDP socket Gradle uses for file
locking**, so Gradle cannot even start. The agent reported:

> Final build status: blocked before compilation… no compiler errors were reached.

**Consequence: "iterate until it compiles" is unenforceable for codex agents here.**
Either grant `--sandbox danger-full-access`, or keep compilation as the reviewer's
checkpoint. **We keep it as the checkpoint** — this round justifies it: the agent's code
looked entirely plausible and contained three real defects.

### 2. Layout resource variants — the defect that would have cost real time

`fragment_playback_panel.xml` exists in **three** variants:

```
layout/            layout-h360dp/            layout-h520dp/
```

The agent patched only `layout/`. Two consequences:

- ViewBinding generated `unrulyCompose` as **nullable** (`ComposeView?`), causing two
  compile errors.
- **The device resolves to `layout-h520dp`** (Redmi Note 10 Pro, 1080×2400 @ ~2.75 density
  ≈ 873dp tall). Had the obvious quick fix been applied — `?.apply` to silence the
  nullability — the build would have compiled, installed, and rendered **nothing**. The
  failure would have looked like broken Compose interop rather than a missed resource
  qualifier.

**Rule: when touching a layout, always `find app/src/main/res -name "<layout>.xml"` first.**
Auxio uses height qualifiers heavily.

### 3. `androidx.compose.ui.platform.setContent` is `internal`

The agent imported it, shadowing the public `ComposeView.setContent` member:

```
e: Cannot access 'fun AbstractComposeView.setContent(...)': it is internal in file.
```

Fix: delete the import. `setContent` is a member function; it needs no import.

### 4. ComposeView draws under sibling views

Constraining the `ComposeView` below the toolbar put it in the same region as Auxio's
`ViewPager2` cover art, which drew on top — the Compose content was visible only where the
art did not cover it, and taps hit the art instead of the button. In `ConstraintLayout`,
z-order follows declaration order.

Fix for the spike: `android:translationZ="100dp"` plus an opaque
`android:background="?attr/colorSurface"`. Applied to all three variants.

This is throwaway — Phase 3.6 replaces this Activity entirely — but without it the Phase 2
manual test (tapping the Compose button) cannot be performed.
