# Task 2.1–2.2 — Compose Dependencies

**Owner:** Claude (direct). Version selection against AGP 9.2.1 / Kotlin 2.3.10 is precisely
where the buildspec warns stale model knowledge produces confident wrong answers.

## What worked: query the repository, don't recall

Rather than writing versions from memory, every version was read from live Maven metadata:

```bash
curl -s "https://dl.google.com/dl/android/maven2/androidx/compose/compose-bom/maven-metadata.xml" \
  | grep -oE "<version>[^<]+</version>" | tail -12
```

This is cheap, authoritative, and immune to training-data drift. **Do this for every
Compose/Media3/AndroidX version added for the rest of the project.**

| Artifact | Chosen | Justification |
|---|---|---|
| `androidx.compose:compose-bom` | `2026.06.01` | latest stable; pins all `androidx.compose.*` |
| `org.jetbrains.kotlin.plugin.compose` | `2.3.10` | **must equal `kotlin_version`** — verified present in the plugin portal |
| `androidx.activity:activity-compose` | `1.13.0` | matches project's existing `activity-ktx 1.13.0` |
| `androidx.lifecycle:lifecycle-runtime-compose` | `2.11.0` | provides `collectAsStateWithLifecycle` |
| `androidx.navigation:navigation-compose` | `2.9.7` | matches project's `navigation_version` |

Declared in `build.gradle` `ext` so versions stay in one place, matching the existing style.
Compose artifacts are declared **without versions** — the BOM supplies them.

## Why 2.2 exists (and it earned its keep)

The buildspec's "build with dependencies present but unused" is a genuinely good instinct:
any version conflict surfaces while the error is unambiguous, before Compose source exists
to muddy the diagnosis. Dependency resolution and configuration both passed, which is the
actual signal 2.2 was looking for.

## Papercuts

**1. First Compose build is slow at `mergeExtDexDebug`.**
Dexing the Compose runtime + Material3 for the first time takes several minutes with no log
output. It looks hung. It isn't — check the Gradle daemon is alive
(`ps aux | grep GradleDaemon`) rather than killing the build.

**2. `navigation-compose` is probably dead weight.**
Buildspec 2.1 lists it, so it was added. But Phase 3.4 gives each skin ownership of its own
navigation ("no shared nav graph, because navigation model is part of a skin's identity")
and Phase 4.5 supplies an optional back-stack primitive. Left in with an explanatory comment
rather than silently dropped — **revisit and likely remove at Phase 3**.

**3. The Compose compiler version is not independent.**
Since Kotlin 2.0 the Compose compiler ships inside Kotlin. `kotlin.plugin.compose` must
track `kotlin_version` exactly — there is no separate `composeCompilerVersion` to set, and
advice to set `composeOptions { kotlinCompilerExtensionVersion }` is obsolete for this
project. Expect models to suggest it anyway.
